# Multi-Agent Research System: інструменти за MCP, агенти за A2A

Розширення попередньої роботи. **Логіка не змінилась жодною мірою**: той самий
Supervisor координує Planner / Researcher / Critic за патерном
Plan → Research → Critique, критик має право повернути роботу, ліміт доробок
живе в коді, а запис на диск дозволяє людина. Змінився **транспорт між
агентами** — замість одного ACP-сервера з трьома агентами всередині тут три
окремі A2A-сервери, у кожного своя Agent Card за відомою адресою.

Друга зміна більша за першу, і вона не про протокол. Ця робота зроблена **на
LangChain**, точно за завданням: агенти через `create_agent`, інструменти через
`langchain-mcp-adapters`, людина в контурі через `HumanInTheLoopMiddleware`. У
попередніх роботах цикл був власний, і кожна з них пояснювала, чому фреймворк не
взято. Тут він узятий навмисно — щоб побачити ту саму систему з іншого боку і
порівняти не на словах.

Порівняння вийшло симетричним. Фреймворк **прибрав цілий модуль** — міст у
фоновий потік, яким зшивались синхронний цикл і асинхронні клієнти. І **додав
контракт**, якого не було: перервання графа з відновленням через checkpointer.
Обидва пункти нижче, з кодом.

Текст завдання — у [TASK.md](TASK.md).

## Швидкий старт

```bash
cd "Homework 10"

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env       # і вписати OPENAI_API_KEY

python ingest.py           # PDF з data/ → чанки → ембеддинги → index/
./start_servers.sh         # Qdrant + 2 MCP + 3 A2A
python main.py
```

`start_servers.sh` перевіряє кожен порт і піднімає лише те, чого немає. Порти він
читає з `.env`, а не тримає зашитими — сервер і скрипт зобов'язані брати адресу з
одного місця, інакше скрипт чекає не там і бадьоро друкує «готово».

Картку агента можна прочитати, **не піднімаючи клієнта**:

```bash
curl -s localhost:8903/.well-known/agent-card.json
```

## Архітектура

```
User (REPL, main.py)
  │
  ▼
Supervisor  (локальний create_agent + HumanInTheLoopMiddleware)
  │
  ├── delegate_to_planner     ──► A2A :8903 ──► MCP ──┐
  ├── delegate_to_researcher  ──► A2A :8904 ──► MCP ──┼──► SearchMCP :8901
  ├── delegate_to_critic      ──► A2A :8905 ──► MCP ──┘
  └── save_report             ──► MCP ──► ReportMCP :8902   (через HITL)
```

| Процес | Порт | Що всередині |
|---|---|---|
| Qdrant | 6333 | вектори, спільні для всіх робіт |
| SearchMCP | 8901 | `web_search`, `read_url`, `knowledge_search` + ресурс `knowledge-base-stats` |
| ReportMCP | 8902 | `save_report` + ресурс `output-dir` |
| A2A planner | 8903 | `create_agent` + `response_format=ResearchPlan` |
| A2A researcher | 8904 | `create_agent`, вільний текст |
| A2A critic | 8905 | `create_agent` + `response_format=CritiqueResult` |
| REPL | — | Supervisor, людина в контурі |

| Агент | Інструменти | Форма відповіді |
|---|---|---|
| Planner | `web_search`, `knowledge_search` | `ResearchPlan` |
| Researcher | `web_search`, `read_url`, `knowledge_search` | текст |
| Critic | `web_search`, `read_url`, `knowledge_search` | `CritiqueResult` |
| Supervisor | `delegate_to_*`, `save_report` | звіт |

### Один сервер = один агент, і це не формальність

Головна зміна проти попередньої роботи. Там був **один** ACP-сервер, усередині
якого три декоратори `@server.agent(name=…)`. Тут три сервери, бо в A2A агент —
це те, що описане карткою, а картка описує **одного**.

Практичне наслідування важливіше за букву. Agent Card — статичний документ за
`/.well-known/agent-card.json`, тож агента можна знайти й описати, **не
піднімаючи його** і не маючи клієнта: достатньо `curl`. У попередній роботі
discovery був викликом до живого сервера (`client.agents()`), тобто щоб
дізнатися, хто там є, треба було, щоб «там» уже працювало. Тут це читання файлу
по HTTP.

Три процеси при цьому **не означають три копії моделі**. Кросс-енкодер на 1.1 ГБ
живе в SearchMCP один на всіх, а агенти отримують інструменти по мережі. Тримай
пошук імпортом — і три процеси коштували б трьох реранкерів; на восьми
гігабайтах це вирішує, поїде система чи ні.

### Набір інструментів — це межі ролі

Планувальнику навмисно не дано `read_url`: з ним він починає читати статті
цілком замість того, щоб скласти план. SearchMCP один на всіх і віддає всім
однаково, тому фільтр стоїть **при збірці агента** — це єдине місце, де ці межі
взагалі проводяться.

### Структурований вивід — це `response_format`, а не розбір тексту

Planner і Critic зобов'язані повернути модель даних, а не прозу. Супервізору
потрібно **прийняти рішення** за відповіддю суб-агента: іти далі чи повертати на
доробку. Рішення за вільним текстом означає, що його знову розбирає модель, і
«APPROVE» усередині фрази «я б не сказав APPROVE» ламає цикл.

У LangChain це один параметр `create_agent(..., response_format=CritiqueResult)`.
У версії з власним циклом того ж домагалися інструментом `submit_*`, чия схема
дорівнює моделі даних, — бо `response_format` є не в кожного провайдера, а
інструменти є у всіх.

### Валідація повторюється на приймальному боці

`_structure()` у супервізорі перевіряє JSON ще раз, і це не недовіра до власного
сервера. Між ними **мережа**: по проводу приїжджає текст, і «це точно
ResearchPlan» лишається припущенням, поки його не перевірили. Не зійшлося —
модель отримує текст помилки й кличе агента ще раз.

### Упалий агент — це рядок, а не виняток

По мережі сусід може не відповісти з причин, до роботи стосунку не мають:
сервер перезапускають, порт зайнятий, процес убитий. Для координатора це звичайне
становище, і дізнатися про нього він має так само, як дізнається про невдалий
інструмент — текстом, з яким можна щось вирішити. Тому провал приїжджає рядком
`ERROR: ...`, і модель вільна покликати ще раз або піти далі.

### Ліміт доробок живе в коді, а не в промпті

Промпт таке дотримує зазвичай, але не завжди, а ціна порушення — нескінченний
цикл на живих грошах. Модель вирішує ЩО робити, код гарантує СКІЛЬКИ. Лічильник
рахує саме вердикти REVISE, а не виклики: критик, що двічі сказав APPROVE, нічого
не витратив.

### Контракт звіту тримає сервер, а не той, хто його кличе

`save_report` відмовляє, якщо в тексті немає розділів `Conclusions` і `Sources`.
Перевірка стоїть у ReportMCP, бо це властивість **звіту**, а не того, хто його
пише: завтра писатиме інший агент, а вимога лишиться тією ж.

### Міст у фоновий потік зник — цілий модуль

У попередній роботі синхронний цикл ReAct і асинхронні клієнти протоколів зшивав
окремий файл `bridge.py`: фоновий потік із власним циклом подій, щоб з
синхронного коду можна було дочекатися асинхронного виклику.

Тут його немає взагалі. LangGraph асинхронний сам, тож делегування — це звичайні
`async def`, а `main.py` починається з `asyncio.run`. Рідкісний випадок, коли
фреймворк прибирає не рядок і не клас, а **файл**.

## Human-in-the-loop: зупинка графа замість `input()`

Найцікавіша різниця, і вона в обидва боки.

`HumanInTheLoopMiddleware` **не питає людину**. Він зупиняє граф: `ainvoke`
повертається, не закінчивши роботу, і в стані лежить `__interrupt__` з описом
того, що агент збирався зробити. Далі справа того, хто викликав, — показати це
людині й запустити граф знову командою `Command(resume=…)`, яка потрапляє рівно в
ту точку, де він став.

Звідси дві речі, яких не було у власному циклі:

**Checkpointer обовʼязковий.** Продовжити зупинений граф можна тільки якщо його
стан десь лежить. У власному циклі «перервання» було викликом `input()`
всередині функції — стек нікуди не дівався, і відновлювати було нічого.

**Цикл живе зовні.** `ainvoke` викликається в `while`, бо підтверджень за один
запит може бути кілька: людина попросила правку, агент переписав звіт і знову
кличе `save_report`.

Що це дає взамін: зупинений граф можна продовжити **в іншому процесі**. На тому
й стоїть уся конструкція LangGraph. Тут ця можливість не потрібна — REPL живе в
одному процесі, — і чесно сказати прямо: механізм потужніший за задачу.

Три відповіді людини виражаються одним каналом:

```
approve  → інструмент виконується, іде виклик ReportMCP
edit     → сервер НЕ кличемо, модель отримує зауваження і править
reject   → сервер НЕ кличемо, модель отримує відмову і зупиняється
```

Зауваження повертаються моделі як `{"type": "reject", "message": …}` — для неї це
невідрізнимо від «інструмент відпрацював і ось що він сказав», і вона переробляє
звіт, не знаючи, що між ними була людина.

Зворотний бік записано в шапці `report_mcp.py`: сервер виконає запис для
будь-кого, хто до нього додзвониться. Ворота стоять у супервізора, а не біля
дверей. Для установки на `127.0.0.1` це прийнятно, але це допущення, а не захист.

### Літерал відповіді людини — рядок, який ніхто не звіряє

Помилка, знайдена перевіряючим уже після здачі, і вона повчальніша за багато чого
в цій роботі.

`_ask_human` повертав `{"type": "accept"}`. Middleware звіряє літерал **рядком** і
знає лише `approve` / `edit` / `reject` / `respond`; незнайоме значення дає
`Unexpected human decision`. Тобто жива людина, яка натиснула «так», отримала б
падіння. Docstring двома рядками вище при цьому казав правильно — код суперечив
власній документації.

**Чому це пережило наскрізний прогін.** Тест підміняв `_ask_human`
автопідтвердженням, і те повертало ПРАВИЛЬНИЙ літерал. Я замінив рівно ту
функцію, у якій сиділа помилка, і перевірив усе, крім неї.

Це класична сліпа зона моків: підміняючи інтерактивну частину, підміняєш і її
контракт. Звідси правило, яке варте більше за саме виправлення:

> **Якщо щось замінюється моком заради тестованості — саме воно зобовʼязане
> перевірятися окремо.**

Тому поруч зʼявився `check_hitl.py`: тридцять рядків, жодного агента, жодного
токена. Три відповіді людини проганяються через справжній `_ask_human`, а
результат — через справжній `_process_decision`.

```
$ .venv/bin/python check_hitl.py
  ✓ approve  -> approve  инструмент исполняется
  ✓ edit     -> reject   не исполняется, модель правит
  ✓ reject   -> reject   не исполняется, модель останавливается
```

## Пастки середовища

**`A2AStarletteApplication` з прикладів не існує.** У `a2a-sdk` 1.1.2 застосунок
збирається з трьох наборів маршрутів — `create_agent_card_routes`,
`create_jsonrpc_routes`, `create_rest_routes` — і вішається на звичайний
Starlette. `fastapi` при цьому **не потрібен**: `add_a2a_routes_to_fastapi`
існує заради `/docs`, а не заради роботи. Там же переїхав `new_text_message` — не
в `a2a.utils`, а в `a2a.helpers.proto_helpers`.

**`cryptography` 50.0.0 не має колеса під x86_64-darwin** і лізе збиратися через
Rust — установка падає цілком. Приїжджає транзитивно й двома шляхами одразу:
`langchain-mcp-adapters → mcp → pyjwt[crypto]` і `mcp → Authlib`. Обидва про
OAuth і JWT, яких ми не використовуємо. Лікується стелею `cryptography<49`:
остання версія з готовим колесом — 48.0.1.

**LangChain не бачить `.env`.** `create_agent(model="gpt-5.2")` збирає клієнта
сам і бере ключ із **змінної оточення**, а `pydantic-settings` кладе значення в
обʼєкт `settings`, а не в `os.environ`. При цілком правильному `.env` виходить
`Missing credentials`. Експорт стоїть у `config.py` — серверів пʼять, і забути
про один із них питання часу.

**Контракт перервання — це протокол, і його можна порушити.** Middleware віддає
`{"action_requests": [...], "review_configs": [...]}` **списком** (модель вправі
покликати два інструменти за хід), а назад чекає `{"decisions": [...]}` рівно
тієї ж довжини. Помилишся формою — отримаєш `TypeError: list indices must be
integers` усередині чужого файлу, без натяку на те, що не так.

Це та помилка, якої у власному циклі **не могло статися в принципі**: там
«спитати людину» — це `input()` усередині функції, і жодного контракту між
сторонами немає. Механізм, який дозволяє продовжити граф в іншому процесі,
платить за це ще одним місцем, де можна розійтися.

**FastMCP 3.x тягне `mcp` 1.x**, тоді як офіційний SDK давно на 2.x. В одному
оточенні їх не сумістити, і це варто знати заздалегідь, якщо в проєкті вже є код
на `mcp` 2.0.

## Приклад роботи

Запит із завдання, нічого не підпилювалось:

```
You: Compare RAG approaches: naive, sentence-window, and parent-child

[Supervisor → A2A → Planner]
  ← план: 8 запросов, источники: both
                                   [planner]    2 863 токенов

[Supervisor → A2A → Researcher]  (раунд 1)
                                   [researcher] 99 968 токенов
[Supervisor → A2A → Critic]
  ← вердикт: REVISE
                                   [critic]     23 798 токенов

[Supervisor → A2A → Researcher]  (раунд 2)
                                   [researcher] 576 589 токенов
[Supervisor → A2A → Critic]
  ← вердикт: REVISE
                                   [critic]     19 410 токенов

[Supervisor → A2A → Researcher]  (раунд 3)
                                   [researcher] 75 912 токенов
   Revision limit reached (2) — звіт пишеться з того, що є

⏸️  ТРЕБУЕТСЯ ПОДТВЕРЖДЕНИЕ
  файл: rag_approaches_comparison.md  (243 строк, 11169 символов)
  👉 approve / edit / reject: approve
  ✅ Report saved to output/rag_approaches_comparison.md

📊 супервизор: 106 335 токенов, доработок: 2
```

Прогін повторив попередню роботу крок у крок: два вердикти REVISE, вичерпаний
ліміт, звіт із того, що є. Готовий звіт має обовʼязкові `Conclusions` і `Sources`
(їх тримає ReportMCP) плюс окремий розділ `What stayed unresolved` — саме те,
чого вимагає гілка «ліміт вичерпано».

Рядки `[planner] 2 863 токенов` приходять **не з відповіді**, а з логів самих
агентів. Кожен рахує свої токени у своєму процесі, і по проводу вони не їдуть —
див. «Ціна» нижче.

## Ціна: заміряно

| агент | токенів | частка |
|---|---|---|
| Researcher | 752 469 | 83.2 % |
| Supervisor | 106 335 | 11.8 % |
| Critic | 43 208 | 4.8 % |
| Planner | 2 863 | 0.3 % |
| **разом** | **904 875** | |

Проти **951 808** у попередній роботі на тому ж запиті. Різниця — пʼять
відсотків, тобто в межах розкиду між прогонами.

Це і є головний висновок заміру. **Ні протокол, ні фреймворк не міняють ціну.**
Змінилося все: ACP на A2A, один сервер на три, власний цикл на LangChain,
`submit_*` на `response_format`, `input()` на зупинку графа. Ціна лишилася тією
ж, і пропорція теж: дослідник зʼїдає вісім десятих, планувальник — три десятих
відсотка.

Платиш не за узгодження і не за транспорт, а за **повторне дослідження**.
Формула та сама, що заміряна раніше:

> ціна ≈ ціна одного агента × (1 + кількість доробок) + накладні на координацію

Другий раунд коштував **576 589** токенів — більше, ніж перший і третій разом.
Причина механічна й не залежить від протоколу: історія дослідника їде в запит на
КОЖНОМУ кроці, а до другого раунду вона вже містить увесь перший разом із
текстами прочитаних сторінок. Перша ціль оптимізації тут та сама, що й була:
возити між агентами витяги, а не повні знахідки.

### Скільки коштує подивитися на ціну

У попередній роботі токени суб-агентів приїжджали частиною `stats` у відповіді
ACP, і сумарна цифра була видна одразу, в тому ж терміналі. Тут її **немає**: у
A2A відповідь — це повідомлення, а не пара «результат + рахунок». Кожен агент
рахує своє й пише в свій лог, а скласти можна лише руками.

Це не докір протоколу. Це нагадування, що **вимірність не безкоштовна**: у hw9
вона зʼявилася не сама, а тому що в `_reply()` дописали другу частину
повідомлення. Не допиши — і порівняння, яке ви щойно прочитали, просто не
існувало б.

## Обмеження

- **Токени суб-агентів не складаються автоматично.** Кожен агент рахує свої в
  своєму процесі й пише в свій лог; у відповіді A2A їде **повідомлення**, а не
  пара «результат + рахунок». У версії на ACP статистика поверталася частиною
  відповіді, і загальна ціна була видна одразу. Тут її треба збирати руками —
  або розширювати `metadata` протоколу під свої потреби.
- **Сервер запису відкритий для всіх на машині.** Див. розділ про HITL.
- **Паралельності немає**, хоча тепер вона можлива: три агенти в різних процесах
  могли б працювати одночасно. Але цикл Plan → Research → Critique послідовний
  за змістом — критикувати нема чого, доки дослідник не закінчив.
- **`a2a-sdk` молодий.** Приклади з лекції не працюють на поточній версії, і це
  не помилка лекції: SDK переїхав. Закладай час на звірку API з реальністю.
- **Три агенти в одному процесі.** Знадвору це три незалежні сервери з трьома
  картками й трьома адресами, і рознести їх машинами можна, не помінявши жодного
  рядка. Але зараз у них спільний інтерпретатор — поступка зручності запуску.
- **Critic не всесильний.** Він перевіряє те, що вміє знайти. Твердження, якого
  немає в жодному доступному джерелі, він не спростує — лише позначить як
  непокрите, і то якщо помітить.
