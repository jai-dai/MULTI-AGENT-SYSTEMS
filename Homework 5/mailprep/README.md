# mailprep — препроцессор почты для локального RAG

Драфт под стек: **Gmail API → mailprep → bge-m3 (Ollama) → Qdrant → MCP**

Дорабатывать в VSCode вместе с Claude Code.

---

## Структура

```
mailprep/
├── models.py           # датаклассы: RawMessage → CleanMessage → Thread → Chunk
├── clean.py            # ★ ЯДРО: обрезка цитат/подписей/дисклеймеров + detect_lang
├── pipeline.py         # склейка цепочек, чанкинг, payload для Qdrant
└── inspect_quality.py  # ★ инструмент отладки паттернов очистки
```

Два файла со звёздочкой — то, где сосредоточена вся ценность.
Остальное — обвязка.

---

## Быстрый старт

```bash
# 1. Выгрузить письма в JSON (свой скрипт на Gmail API)
python dump_gmail.py > dump.json

# 2. Посмотреть, как отрабатывает очистка
python -m mailprep.inspect_quality dump.json -v

# 3. Разобрать конкретное письмо
python -m mailprep.inspect_quality dump.json --id 18f2a3b4c5

# 4. Дополнить паттерны в clean.py, повторить шаг 2
```

## Как читать отчёт inspect_quality

| Метрика | Что означает |
|---|---|
| `пустые после очистки` высокий % | Паттерны **слишком жадные** — режут полезный текст |
| `почти не тронуто` высокий % | Паттернов **не хватает** — цитаты/подписи остаются в индексе |
| `перечистили` (остаток <15%) | Смотреть глазами: где эвристика ошиблась |
| `недочистили` (остаток >95%) | Смотреть хвост: какой паттерн подписи не покрыт |

Цель — довести оба крайних показателя до минимума на **своих** данных.
Универсальных паттернов не существует, у каждой переписки свой мусор.

## Ключевые решения (и почему)

**1 письмо = 1 чанк.** Резать письмо по 512 токенов бессмысленно — оно и так
короткое, а разрыв контекста хуже, чем длинный чанк. Длинные письма
(>4000 симв.) режутся по абзацам с overlap 300.

**Контекстная шапка перед эмбеддингом.** Каждый чанк начинается с
`Тема: ... | От: ... | Дата: ...`. Без этого письмо «да, согласны, 14 недель»
не находится ничем. Это главный приём для качества RAG по почте.

**Порядок очистки важен.** noise → quote header → quoted lines → disclaimer →
signature. Подпись режется последней и только в последних 15 строках —
иначе слово «Regards» в середине текста убьёт полписьма.

**detect_lang без внешних зависимостей.** Различает ru/uk по характерным
буквам (і/ї/є/ґ vs ы/ъ/э/ё). bge-m3 мультиязычный, так что на эмбеддинг
не влияет — нужно для фильтров и отладки.

## Что доработать (по порядку)

### 1. Паттерны под свои данные — обязательно
В `clean.py` расширить: `QUOTE_HEADERS`, `SIGNATURE_MARKERS`,
`DISCLAIMER_STARTS`, `NOISE_LINES`. Особенно корейские варианты, если
переписка с Doosan / GS / Woojin пойдёт активно.

### 2. Ридер Gmail
Написать `dump_gmail.py` на `google-api-python-client`. Отдавать JSON в
формате, который ждёт `load_dump()` (описан в докстринге).
Scope: `gmail.readonly`.

### 3. Эмбеддинги
```python
import httpx
def embed(texts: list[str]) -> list[list[float]]:
    r = httpx.post("http://localhost:11434/api/embed",
                   json={"model": "bge-m3", "input": texts}, timeout=120)
    return r.json()["embeddings"]
```

### 4. Qdrant + гибридный поиск
bge-m3 умеет dense + sparse одновременно. Через Ollama обычно доступен
только dense — для sparse либо поднять FlagEmbedding напрямую, либо
взять BM25 отдельно и слить результаты (RRF). Для деловой почты
гибрид критичен: точные совпадения (имена, номера `ATON-DE/2026-001`,
домены) векторный поиск размывает.

Индексы в Qdrant поставить на: `thread_domains`, `lang`, `date`,
`has_attachments` — это основные фильтры.

### 5. MCP-сервер
Два инструмента достаточно:
- `search_mail(query, domain?, date_from?, date_to?, limit?)` → список чанков
- `get_thread(thread_id)` → полная цепочка

SDK: `pip install mcp`.

## Идеи на потом

- **Дедупликация**: одно и то же письмо часто приходит и в INBOX, и в SENT.
  Хэш по (нормализованная тема + дата + первые 200 симв.).
- **Извлечение сущностей**: номера документов, суммы, даты, Incoterms —
  в payload отдельными полями, чтобы фильтровать точно.
- **Приоритет свежести**: при равной релевантности поднимать свежие письма.
- **Вложения**: сейчас только имена файлов. PDF-вложения (КП, спецификации)
  логично парсить и индексировать отдельной коллекцией.
