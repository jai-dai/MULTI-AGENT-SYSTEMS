# Порівняння naive RAG та sentence-window retrieval

У цьому звіті досліджено та порівняно два підходи до Retrieval-Augmented Generation (RAG): naive RAG та sentence-window retrieval. Розглянуто їхні механізми, переваги, недоліки та особливості застосування.

## Naive RAG

Naive RAG — це базовий, найпростіший варіант RAG, який складається з трьох основних фаз:

- **Індексація даних:**
  - Завантаження документів.
  - Розбиття великих документів на менші частини (наприклад, по 500 символів).
  - Перетворення цих частин у векторні ембедінги.
  - Збереження ембедінгів у векторній базі даних.

- **Пошук:**
  - Запит користувача перетворюється у вектор.
  - Пошук найбільш схожих векторів у базі для знаходження релевантних частин тексту.

- **Генерація:**
  - LLM отримує запит і релевантні частини тексту для генерації відповіді.

### Проблеми naive RAG

- Можливість пропуску релевантних частин або отримання нерелевантних.
- Складнощі з інтеграцією контексту, особливо якщо релевантні частини розкидані або повторюються.
- Ризик генерації відповідей, які не базуються на наданому контексті.

## Sentence-window retrieval

Sentence-window retrieval — це вдосконалений підхід, який базується на розбитті тексту на окремі речення, але при цьому для кожного речення зберігається контекст у вигляді сусідніх речень ("вікно" навколо речення).

- Для кожного речення обчислюється векторний ембедінг.
- Під час пошуку знаходиться найбільш релевантне речення за ембедінгом.
- До LLM подається не лише це речення, а й сусідні речення, що дає ширший контекст.

### Переваги

- Збереження смислової цілісності речень, уникнення розриву інформації, що може статися при простому розбитті на фрагменти за кількістю символів.
- Допомагає LLM краще розуміти зв’язки між реченнями, наприклад, розпізнавати, до чого відносяться займенники.
- Баланс між розміром контексту і точністю пошуку: не занадто великі фрагменти, щоб не розмивати семантику, але достатньо контексту для розуміння.

### Недоліки

- Вибір розміру "вікна" сусідніх речень є критичним: занадто великий розмір може знизити продуктивність системи.

## Порівняння

| Характеристика               | Naive RAG                              | Sentence-window retrieval                  |
|-----------------------------|--------------------------------------|--------------------------------------------|
| Розбиття тексту             | Фіксовані фрагменти за кількістю символів | Речення з контекстом сусідніх речень       |
| Контекст для LLM            | Лише знайдені фрагменти               | Речення + сусідні речення (вікно)          |
| Точність пошуку             | Може пропускати релевантні дані       | Краща точність завдяки контексту            |
| Ризик розриву інформації    | Високий (інформація може бути розділена) | Низький (збереження цілісності речень)     |
| Складність реалізації       | Простий                              | Складніший через обробку контексту          |

## Висновки

Sentence-window retrieval є покращенням naive RAG, особливо у випадках, коли важливо зберегти контекст і цілісність інформації. Він допомагає уникнути проблем з розривом інформації та покращує якість відповідей LLM. Однак вибір параметрів, таких як розмір вікна, є важливим для оптимальної роботи системи.

Naive RAG підходить для простих задач або коли немає можливості складно обробляти контекст, але може бути менш точним.
